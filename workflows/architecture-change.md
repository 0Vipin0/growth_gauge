# Workflow: Architecture Change

## Objective

Safely modify an established architectural boundary.

## Skills

Apply:

- Repository Discovery
- Architecture Discovery
- Convention Discovery
- Architecture Review
- Testing
- Change Review

## Process

1. Document the current architecture.
2. Identify the actual problem.
3. Identify affected boundaries.
4. Evaluate alternatives.
5. Determine migration strategy.
6. Define scope.
7. Implement incrementally.
8. Update tests.
9. Update architecture documentation.
10. Perform architecture review.
11. Perform final change review.

## Rules

Architecture changes require stronger justification than feature changes.

Do not perform broad migrations without explicit authorization.

Prefer incremental migration over large rewrites.
